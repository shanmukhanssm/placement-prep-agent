## Decisions Made During Intake

- **Single-user app:** one BTech student; one SQLite-checkpointed thread per chat session; no multi-user concerns in v1.
- **LLM provider:** Groq via the OpenAI-compatible client (`ChatOpenAI(base_url=$LLM_BASE_URL)`); exact model choice parked with the owner.
- **Router:** conversational LLM intent classification — NO commands; smalltalk/low-confidence falls back to clarify.
- **Core subject:** chosen once at onboarding, fixed afterwards (`aiml | cyber`).
- **HTML report card:** in v1 scope; template designed with the owner later (Phase 1 ships a minimal readable table).
- **Model placeholder:** `llama-3.3-70b-versatile` until the owner decides; model strings sourced only from `config.py`.
- **Trends:** computed in Python only (`compute_trend`); the LLM narrates precomputed numbers, never computes them.
- **DSA shape:** 2 roles (selector/evaluator), 1 problem/session, pass = optimality ≥80 or give-up, ≤3 attempts.
- **Interaction:** turn-based — one user message = one graph invocation; no `interrupt()` in v1; the CLI loop is the human gateway.
- **Tooling:** pytest / ruff / mypy where they earn their keep — strict on `src`, pragmatic on tests and fixtures.
- **LLM provider (2026-09-14, owner instruction):** Ollama cloud via `.env` only — `LLM_BASE_URL=https://ollama.com/v1`, `LLM_API_KEY` (owner-provided; 401 at the Phase 2 smoke — invalid/expired), `LLM_MODEL=gpt-oss:120b-cloud`. ## Caveats Learned

- **`SqliteSaver` serializer kwarg is `serde`, not `serializer`** (langgraph 1.2.11) — and pydantic models stored in checkpoints need an explicit msgpack allowlist or every round-trip warns "Deserializing unregistered type" (becomes a hard block in a future version). Encapsulated in `graph.make_sqlite_checkpointer`; recorded in library-docs.md.
- **`config.py` reads `LLM_API_KEY` with an empty-string default in Phase 0** (docs show hard-required `os.environ[...]`) — deliberate: stubs never call the LLM and tests stay hermetic. Phase 3.1 must enforce the key (fail fast in `get_llm` when an LLM role is requested) and this caveat retires. *(Phase 2 note: `call_structured` now constructs the client inside its try, so a missing/invalid key degrades to the node fallback instead of crashing the turn — loud fail-fast still owed at 3.1.)*
- **LangGraph silently DROPS unknown keys from node returns and invoke inputs** (verified on 1.2.11) — so `extra="forbid"` on the sub-states is what makes typo'd namespace keys fail loudly, but only at the wrapper's `model_validate` call. Never move the boundary mapping to raw dict pass-through.
- **Conditional-edge path maps must contain an `END: END` entry whenever the router can return END** — a router returning a key missing from the map raises `KeyError: '__end__'` mid-run (hit in 0.2, fixed same commit).
- **compute_trend ordering home:** registry signature is `list[float]`, so the "sorted by record date, never insertion order" rule is enforced by the CALLER — `save_session_results` rebuilds each field's score list date-sorted from history before computing. Callers must pass date-ascending scores; blind append would break the order-independence property (proved by `test_save_shuffled_insertion_order_same_verdict`).
- **avg_prev3 semantics:** previous window = up to 3 scores before the last-3 window (1–3 scores). Required by the eval-plan "4th record flips from not_enough_data" case; exactly 3 scores still yields `not_enough_data` (empty comparison window).
- **save card-write failure leaves history ahead of card:** v1 two-file consistency is best-effort (each file atomically written, history first). A `ok:false` on the card write keeps the audit trail; the NEXT successful save heals the card because scores are rebuilt from history. Duplicate `record_id` re-saves are true no-ops either way.
- **No push credentials in the agent session envs** — commits live on local `main` until the owner pushes (or provides GITHUB_USERNAME/GITHUB_TOKEN / `gh` auth).
- **Phase 2 (2026-09-14): caller mints `record_id`, tool owns the seq.** `save_session_results` computes the file's per-day seq, but the wrap node composes the idempotency key — so every wrap counts today's same-field records via `read_report_card` before minting `{date}-{field}-{seq}`. The Phase 0 stubs hardcoded `-1`, which would have made a second same-day session a silent duplicate no-op. Ceiling: `recent_history` caps at 10/day/field — fine at single-user volume.
- **Phase 2: a specialist turn that must NOT ask the next question ends via an explicit state signal.** comm sets `phase="probe"`/`"done"`, core additionally checks `quit_pending` in `route_after_judge`; the core judge's score branches MUST reset `phase="ask"` or the stale `"probe"` routes the next user message to the examiner and silently skips judging it (found by the probe test, fixed same commit).
- **Phase 2: canonical topic names must not contain commas.** The core record's `topic` is comma-joined canonical names (behavior-core §6), so the AIML topic "accuracy, precision, recall, F1" was renamed canonically to `accuracy-precision-recall-f1` ("hyphenated where needed" per §6) — a comma inside a name would corrupt both the record format and the rotation parser.
- **Phase 2: cross-session per-topic scores are approximated at record level.** `SessionRecord` questions carry no topic field, so the spaced re-test exception (behavior-core §2.4 rule 4) uses the record's mean score for every topic in it. Exact per-topic history needs a record-shape change (owner call, v1.1).
- **Phase 2: `__main__` must load `.env` BEFORE importing `config`.** config reads env at import time; the loader therefore runs first with `noqa: E402` imports. Also verified: ChatOpenAI construction fails loudly on an empty key, so `call_structured` builds the client inside its try (graceful degradation) — Phase 3.1 should still enforce the key fail-fast.
- **Phase 2: provider key invalid (401).** The Ollama cloud key from the owner is rejected by `ollama.com` (both `/v1` and `/api`, curl-verified) — every Phase 2 LLM role degraded to its documented fallback during the live smoke, proving the failure ladder, but no live LLM output was verified. Rerun the CLI smoke + full eval suite once a working key lands.
- **Phase 3.1: `greet_returning` is currently UNREACHABLE from the routing topology.** graph-design.md's edge table maps intents → branches (`onboarding`, `dsa_session`, `comm_session`, `core_session`, `progress_talk`, `farewell`, `clarify`) but has no "greet" intent. The node is implemented per spec (LLM call + templated fallback, number-integrity rule) and unit-tested directly via the node function (`test_returning_user_golden_flow` exercises clarify/progress_talk/farewell; greet_returning's number-integrity is verified via the same `_trend_json` helper). Wiring greet_returning into the routing is a future-owner decision (add a "greet" intent that fires on turn-1 of a returning user, or merge it into progress_talk) — recorded here, not in graph-design.md, because the topology did not change in 3.1.
- **Phase 3.1: number-integrity check is strict on digit numerals.** The Layer 4 grader regex (`\d+(?:\.\d+)?`) extracts every digit numeral from `assistant_message` and asserts each is verbatim in the injected `trend_summary` JSON. Hardcoded counts in the templated fallback (`"last 3 avg"`) would invent the numeral `3`, so `_verdict_line` uses `"recent avg"` instead. Spelled-out number words ("three") are out of v1 scope per eval-plan.md.
- **Phase 3.1: `clarify` prompt passes `confidence=0.5` placeholder.** state.intent is a normalized string (low-confidence → "smalltalk" inside route_turn), so the original confidence is lost by design. The CLARIFY_V1 prompt template carries `{confidence}` per prompt-registry.md; the node substitutes a conservative 0.5 (below the 0.6 floor, explaining why clarify fired). Storing the original confidence would require a state-field addition + graph-design.md update — parked as a v1.1 candidate.
- **Phase 3.1: intent seed set is 26 utterances (≥24 per eval-plan L2).** Composition: 4 explicit dsa + 4 indirect dsa + 3 communication + 4 core_subject (incl. the "explain greedy algorithm" trap → core_subject NOT dsa) + 3 progress + 3 smalltalk + 2 ambiguous low-confidence (normalize to smalltalk) + 3 exit = 26. The composition gate counts gold labels (≥3 smalltalk), so the 2 ambiguous entries don't count toward the smalltalk bucket — they verify the normalization path separately. Live-LLM accuracy at ≥95% is the Layer 2 gate in Phase 4; this test proves the routing LOGIC for every gold intent.
- **Phase 3.2: HTML validator must skip void elements.** Python's `html.parser` does NOT auto-pop void elements (`<meta>`, `<br>`, `<hr>`, `<img>`, `<input>`, `<link>`, etc.) — it calls `handle_starttag` for them but never `handle_endtag`. A validator that pushes them onto the open-tag stack will false-positive on every page that uses `<meta charset="utf-8">` (the `</head>` end-tag mismatches stack-top `meta`). Fix: skip void elements at push time in `handle_starttag`, ignore stray void end-tags in `handle_endtag`. Encoded in `tests/unit/test_render_template.py::_HTMLValidator` with a `_VOID_ELEMENTS` frozenset.
- **Phase 3.2: badge text contract preservation.** The new template renders trend verdicts as colored pill badges. The `not_enough_data` verdict's badge text must read "no data yet" (not "not enough data") to preserve the Phase 1 contract — `test_tools_render.py::test_render_healthy_data_contains_every_field_and_latest_score` asserts `"no data yet" in page`. Encoded in the `_VERDICT_LABEL` map in `render.py`; the CSS class `verdict-not_enough_data` is unchanged (the visual style is decoupled from the visible label).
- **Phase 3.2: per-session history table parked.** The build-plan says the template covers "recent history" but the v1 card model (`_ReportCardFile` in `report_card.py`) doesn't carry per-session history — only per-field score lists + trend verdicts. The Scores & Trends table already shows per-field session counts and latest scores; a separate history list would duplicate that without adding signal at v1's single-user volume. The Recent Sessions section renders a placeholder pointing at `data/history/` (the append-only audit trail). A real per-session history table needs a card-shape change (read `data/history/` from the render tool) — parked until the owner asks, recorded here.
- **Provider swap (2026-09-15): xkiro free-tier occasionally returns an error string in `content`.** Observed once in the live CLI smoke (turn 2: `⚠ Could not execute to...` instead of a tool call). `call_structured`'s `_extract_structured` logs a warning and falls through to the single retry; if the retry also fails, the calling node applies its documented deterministic fallback (router → smalltalk/clarify · greetings → templated numbers from `trend_summary`). The graph stayed live and produced a sensible reply — the failure ladder worked. If this becomes a recurring blocker in Phase 4.1 eval (≥95% intent accuracy over many runs), the lever is either bumping `LLM_REQUEST_TIMEOUT` or adding a free-tier-aware retry policy inside `call_structured`. Not needed today — the smoke passed.
- **Phase 4.1: the eval runner must sanitize the env for the Layer-1 pytest subprocess.** `evals.run` loads `.env` before importing config (same env-before-import contract as `__main__`) — those variables would be inherited by the `pytest -m unit` subprocess. `tests/unit/test_route_turn.py::test_get_llm_bounds_request_timeout_and_retries` pins `timeout == 60.0` (the config DEFAULT), so an inherited `LLM_REQUEST_TIMEOUT` (e.g. the `.env.example`'s own recommended 180) fails that test deterministically. `evals/layer1.py` strips `LLM_*` vars for the subprocess (the suite's designed hermetic mode). The underlying test-hermeticity bug is REPORTED (bug report B-4), not fixed.
- **Phase 4.1: `prep_agent.nodes.greetings` binds `get_llm` at module import — `monkeypatch.setattr(config, "get_llm", ...)` does NOT intercept the four greeting nodes' plain-text calls** (verified: `greetings.get_llm is config.get_llm` stays True after patching config only). Consequences: (a) the L4 forced-fallback seam patches `prep_agent.nodes.greetings.get_llm` directly; (b) the e2e tests' `llm_queues["clarify"/"progress_talk"/"farewell"]` seeds are DEAD SEEDS — in tests those nodes really construct a ChatOpenAI against the env-configured endpoint and, on failure, degrade to the templated fallback (which is what the numeral-integrity assertions actually exercised). `comm_wrap` is unaffected (it re-imports get_llm inside the function at call time). Recorded as bug-report B-3 adjacent context, not fixed.
- **Phase 4.1: live greeting turns put `str(AIMessage)` (the full pydantic repr incl. token-usage metadata) into `assistant_message`** — `_llm_narrate`'s `str(message)` and `comm_wrap`'s `str(get_llm(...).invoke(prompt))` never go through `.content`. Invisible in tests (string stubs / raised calls → fallback path), devastating live: the student sees `content='...' additional_kwargs=...` and the number-integrity rule explodes on token counts. Root cause of the L4 12/12 live reds and G2's 3× narration failures. REPORTED as bug-report B-1 (top severity); not fixed per owner instruction.
- **Phase 4.1: the live model rounds numbers despite the verbatim rule** — progress/greet narration says "74%", "72% to 50%" where the trend JSON carries 74.0/72.0/50.0; the Layer-4 grader (strict by design: "zero invented or rounded numbers") correctly fails these. Even with B-1 fixed, L4 needs the model to quote the exact JSON numerals — a prompt-adherence vs grader-strictness tension the owner should adjudicate (loosen nothing per the eval-plan; prompt-fix lever parked). REPORTED as bug-report B-2.
- **Phase 4.1: Layer-5 golden-case graders take the `data/` DIR, not the workspace root.** The tools resolve `data/` from CWD, so in a workspace the file system of record lives at `<workspace>/data/` — passing the workspace root makes every grader silently look one level too high (found via a line-trace on `read_history` after a false "0 records" reading; the product's record file was present and valid the whole time). Also: the G2 card expectation is per-field (seeded dsa records + 1), not total-history+1.
- **Phase 4.1: the sandbox kills long-lived background processes (setsid/nohup included)** — Layer 5's 9 runs are therefore executed ONE per process by `scripts/layer5_driver.py`, each appending to `evals/results/layer5-partial.jsonl`, then assembled by `--assemble` into the standard results artifact. Deterministic red rows carry the workspace-preserving note; failed runs can be kept via `EVAL_KEEP_WORKSPACES=1`.
- **Harden H1: the CLI thread_id now persists in `data/cli-thread.txt`** — before the fix, `chat_loop` minted a fresh thread per process, so the build-plan's kill-and-resume manual check ("kill -9 during a DSA session, restart CLI, session continues") could NEVER pass through the CLI even though the graph itself resumes fine given the same thread. Resume = same thread_id + the `session_active` pin; `python -m prep_agent --new` opts into a fresh thread. Cross-process resume also re-exercises the msgpack pydantic allowlist on a cold sqlite connection.
- **Harden H1: resume is at TURN-boundary granularity, not mid-node** — the kill-resume test SIGKILLs between invokes (LangGraph checkpoints per superstep; a mid-node kill would re-execute that node on resume — at-least-once semantics per the skill — but this graph's only side effects are the idempotency-tested tools, so a re-run is safe by construction). Mid-node fault injection NOT separately tested — recorded as the v1 limit.
- **Harden H1: `dsa_wrap` makes NO LLM call** (code-composed reveal + record; the statement is bank-verbatim since Change-2) — anything seeding a `"dsa_wrap"`/`"dsa_selector"` role queue will leave it unconsumed; only `dsa_evaluator` and the main-graph roles call the LLM.
- **Harden H1: `compute_trend` needs ≥4 scores for improving/declining** — exactly 3 scores still yields `not_enough_data` (empty comparison window; avg_prev3 semantics), so a seeded "improving in 3 sessions" fixture is a contradiction.
- **Harden H1: importing `prep_agent.__main__` eagerly builds the studio graph** (module-level `from prep_agent.graph import graph`) — the kill-resume driver therefore briefly holds two sqlite connections to the same file (harmless; only the graph writes). A lazy import would remove it — parked.
- **Harden H2: `SessionRecord.date`/`record_id` were filesystem-adjacent** — `save_session_results` interpolates them into `data/history/{date}-{field}-{seq}.json`; a record with `date="../../etc"` would have escaped the data dir. Now: ISO-date pattern + filename-safe charset + after-validator pinning record_id to `{date}-{field}-{seq}` → traversal dies at the tool boundary as `ToolError("invalid_record")`. All seeded datasets (golden cases g1-g3, unit fixtures) verified compatible with the stricter schema.
- **Harden H2: prompt-layer injection defense is honestly thin (spec R1)** — user text is NOT delimited (`--- begin untrusted ---`) and no detector strips instruction-shaped text; judges/classifier are themselves LLMs. The REAL boundary is the capability layer: schema bounds (0-10/0-100/9-intent Literal), code-owned math, closed branch map, data/-only writes. Don't claim detector coverage that doesn't exist — the spec records it as an accepted residual risk with a review date instead.
- **Harden H2: the memory channel is the one place text IS filtered in code** (`memory.py` `_GUARD_PATTERNS` refuses directive-shaped values) — because memory persists into FUTURE turns; judges only affect the current record. Worth remembering when extending either.
- **Harden H2: pattern-validation trade-off** — `record_id` charset is deliberately permissive (`[A-Za-z0-9_-]`) plus the exact-shape after-validator, rather than a rigid template pattern: minting stays the wraps' job and old exports stay loadable. Tighten only if a second writer ever appears.
- **Harden H3: CI stays green WITHOUT secrets by design** — the keyless guard falls back to L1 with a loud `::notice` (live layers 2-5 without a key would burn red runs and train everyone to ignore the gate). Trade-off recorded: a red L2 on push means either a real misroute or a missing secret — check the notice first.
- **Harden H3: empty-string CI secrets would override config fallbacks** (`LLM_BASE_URL=""` → `float("")`-style hazards are guarded in config, but an empty base_url would override the Groq default) — harmless today because the keyless path only ever reaches L1, whose subprocess sanitizes all `LLM_*` vars; if live layers are enabled, set base_url/model secrets to real values, not empty strings.
